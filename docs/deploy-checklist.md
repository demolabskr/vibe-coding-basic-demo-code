# 배포 점검표

내 컴퓨터의 사이트를 인터넷에 올리기 전과 올린 뒤에 확인할 것을 모았다. 특정 호스팅 서비스의 메뉴 대신 어디서나 통하는 항목으로 적었다. 요금과 무료 범위는 각 서비스의 공식 홈페이지에서 확인한다.

## 올리기 전

- [ ] `uv run python manage.py test`가 모두 통과한다
- [ ] 운영 환경 변수로 `uv run python manage.py check --deploy`를 돌려 경고를 읽었다(HSTS 하위 도메인, 미리 불러오기 목록 경고는 내 도메인 사정에 맞춰 판단한다)
- [ ] `DJANGO_DEBUG`를 넣지 않았거나 `false`다
- [ ] `DJANGO_SECRET_KEY`를 개발용과 다른 새 값으로 만들었다
- [ ] `DJANGO_ALLOWED_HOSTS`와 `DJANGO_CSRF_TRUSTED_ORIGINS`에 내 도메인만 적었다("*" 금지)
- [ ] `DATABASE_URL`이 운영 데이터베이스(PostgreSQL)를 가리키고, 백업이 켜져 있다
- [ ] 결제 키는 운영 서버의 환경 변수에만 있다. 저장소와 `.env.example`에는 예시값만 있다
- [ ] 판매 파일(`private/`)과 표지(`media/`)를 둘 곳을 정했다. 컨테이너를 다시 띄워도 지워지지 않는 저장소(디스크나 객체 스토리지)여야 한다
- [ ] 관리자 계정의 비밀번호가 길고, 쓰지 않는 운영자 계정이 없다

## 올리는 순서

1. 저장소의 `Dockerfile`로 이미지를 만들거나, 앱 플랫폼(PaaS)에 저장소를 연결한다.
2. 플랫폼의 환경 변수 설정에 위 값을 넣는다.
3. 띄울 때 `migrate`가 먼저 돌고 `gunicorn`이 사이트를 띄운다(`Dockerfile`의 마지막 줄).
4. 도메인을 연결하고 HTTPS 인증서가 발급되었는지 본다.
5. 결제 대행 서비스 관리 화면에 웹훅 주소 `https://내 도메인/payments/webhook/`을 등록한다.

## 올린 뒤

- [ ] 방문자, 회원, 구매자로 각각 목록, 상세, 구매, 내려받기를 눌러 본다
- [ ] 없는 주소를 열어 사이트 모양의 404 화면이 나오는지 본다(디버그 화면이 나오면 안 된다)
- [ ] `/media/files/...`처럼 판매 파일 주소를 짐작해 열어도 받을 수 없다
- [ ] 로그에 `결제 확인 성공`과 `구매 확인 메일 발송`이 찍힌다
- [ ] 매일 아침 `python manage.py sales_report`가 돌도록 예약 작업을 걸었다
- [ ] 오류 알림(로그 모니터링이나 오류 알림 서비스)을 받을 곳을 정했다
